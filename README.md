# UI Automation Framework (Page Object Model) `🚧 Work in progress`

Фреймворк для автоматизированного тестирования веб-интерфейсов на Python с использованием Selenium WebDriver и pytest. В проекте в качестве примера используется сайт https://store.steampowered.com/.

Проект построен на паттерне **Page Object Model (POM)**, что делает код тестов переиспользуемым, читаемым и легко расширяемым.

---

## Архитектура

### BasePage
Базовый класс, от которого наследуются все страницы. Содержит общие методы:
- `open()` — открыть страницу по URL
- `is_element_present(how, what)` — проверить наличие элемента
- `is_element_visible(how, what)` - проверить виден ли элемент
- `should_be_on_page(expected_path)` — проверить текущий URL через `urlparse`

### Page Objects
В проекте для тестов используется 3 страницы: главная страница логина и регистрации. Каждая страница представляет из себя отдельный класс, который имеет:
- свои локаторы
- свои действия (методы)
   
### Locators
Все локаторы вынесены в locators.py и сгруппированы в классы по страницам. 

## Установка и запуск

1. Клонировать репозиторий
```bash
git clone https://github.com/nyanfisa/page-object-selenium-tests.git
cd page-object-selenium-tests
```
2. Создать и активировать виртуальное окружение
```bash
python -m venv venv
```
# Windows:
```bash
venv\Scripts\activate
```
# Linux/macOS:
```bash
source venv/bin/activate
```

3. Установить зависимости
```bash
pip install -r requirements.txt
```

5. Запустить тесты

```bash
pytest -sv
```

## Что покрывают тесты

Проект состоит из 2 тестов:
1. На заполение логина и пароля в форме авторизации
- Открытие главной страницы
- Проверка наличия ссылки на страницу логина
- Переход на страницу авторизации
- Проверка URL страницы логина
- заполнение полей формы авторизации

2. На появление ошибки при заполнии полей регистрации некорректными данными
- Открытие главной страницы
- Проверка наличия ссылки на страницу логина
- Переход на страницу авторизации
- Проверка URL страницы логина
- Переход на страницу регистрации
- Проверка URL страницы регистрации и наличия всех элементов формы регистрации
- заполнение полей формы авторизации корректными и некорректными значениями
- Проверка появления сообщения об ошибке при вводе некорректных данных в форму и нажатии на кнопку "Продолжить"

## Особенности тестируемого сайта и ограничения

Steam использует несколько уровней защиты, которые делают полный E2E-сценарий неавтоматизируемым.

### 1. Steam Guard (аутентификация)
После ввода логина и пароля Steam требует код подтверждения из email. Без прохождения этого шага авторизация не завершается.

**Следствие:** позитивный сценарий логина не автоматизируется.

### 2. CAPTCHA при регистрации
При отправке формы регистрации Steam показывает капчу для защиты от ботов. В автоматизированном тесте CAPTCHA не проходится.

**Следствие:** позитивный сценарий регистрации не автоматизируется.
Тест на успешную регистрацию помечен `xfail` с пояснением.

### 3. Подтверждение email при регистрации
После отправки формы Steam отправляет письмо со ссылкой для подтверждения. Без перехода по ссылке аккаунт не активируется.

**Следствие:** даже при обходе капчи полный цикл регистрации не автоматизируется.
